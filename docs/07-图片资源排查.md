## 书籍封面持久缓存

书籍目录、书架、解析推荐共用 `BookCard`，与书籍详情页一起接入同一份文件缓存。书籍数据接口仍会获取当前信息和封面版本，但相同 URL 与版本的封面只检查本地文件，不再下载图片；同一版本的并发请求共用一次下载。索引和已保存文件可以跨小程序启动复用。

更新规则：

- 封面 URL 或接口返回的 `coverVersion` 变化：下载新版。旧版交给容量淘汰机制清理，避免晚完成的旧下载删掉正在展示的新版。
- 服务端 `/assets/books/` 文件以修改时间和大小组成版本；图片文件替换后自动变化，下载 URL 携带版本参数。若部署保留相同修改时间且文件大小也不变，此方法无法识别，需使用新文件名或升级内容哈希。
- 远程封面使用书籍更新时间作版本，保留原 URL 与签名参数；原 URL 的内容更换后，在后台保存书籍以刷新（远程 CDN 也需正确更新）。
- 缓存文件被系统删除或图片无法解码：移除失效记录并重新获取；图片错误自动重试一次，继续失败时显示占位，详情页可手动重试。

缓存最多 64 个文件、总计 8 MiB，优先淘汰最久未使用的封面，只删除该索引管理的文件。单张超过 1 MiB 的图片只使用本次临时文件，应先在服务端压缩。下载、保存或本地存储失败会回退临时文件或远程 URL，避免让书籍数据加载失败。H5 使用浏览器原生 HTTP 缓存，不使用小程序文件 API。

上线需要同步发布服务端的 `coverVersion` 字段，并在微信后台配置图片来源的 `downloadFile` 合法域名（当前自有封面为 `api.131462.cloud`）。旧后端仍可显示和缓存图片，但原 URL 替换内容时缺少版本刷新依据。

缓存验证：新增客户端缓存/显示测试 24 项通过；前端完整 Jest 32 项通过；服务端书籍与管理后台定向测试 12 项通过；前后端构建、类型检查和资源自检通过。尚未进行微信真机文件配额与离线缓存验收。

## 本地服务未启动时的响应

启动登录不再自动连续重试，也不显示会阻塞页面的全局加载遮罩。开发环境 API 为 `localhost` 时默认请求超时为 5 秒，线上地址仍为 30 秒；微信登录本身最多等待 5 秒。AI 润色保留原 30 秒超时，显式超时配置可覆盖默认值。首页只保留一次登录/加载任务，失败后释放加载状态并显示“重新连接”，避免 App 生命周期和首页 `onShow` 重复发起登录。

解析结果的降级轮询在网络请求失败后立即结束并显示错误；只有服务端明确返回处理中时才继续轮询。`node scripts/home-loading-self-check.cjs` 与 `node scripts/result-polling-self-check.cjs` 均通过。并发旧请求返回 401 时仅注销同一个旧会话一次，避免连续跳转或误清除新 token；异常 HTTP 响应也会明确拒绝，不留下悬空 Promise。`node scripts/startup-self-check.cjs` 验证初始化、超时、异常响应及 401 防护，通过。

微信开发工具的命令行服务端口关闭，未自动启用，暂未进行模拟器内重放验收。

## 服务端图片与部署

- 78 张塔罗牌面、7 张种子书籍封面在 `server/public` 中均存在。Nest 提供 `/assets/` 服务，生产 Dockerfile 也复制了该目录。
- 使用系统 curl 对 `https://api.131462.cloud` 下这 85 个图片地址逐一执行 HEAD，均返回 `200` 和 `image/jpeg`。这证明检查时地址和响应类型可用，不代表已在微信真机成功解码。
- 初次使用 Python urllib 检查全部出现 TLS 握手超时，系统 curl 随后全部成功；不能把前者当成线上不可用的证据。
- 上传头像通过 `/uploads/avatars/` 提供服务，生产配置有持久化卷。头像地址依赖服务端 `BASE_URL` 配置。
- 开发接口为 `http://localhost:3333/api/v1`，手机无法用 localhost 访问开发电脑；真机联调需要可访问的服务地址。
- `manifest.json` 中开发工具关闭了 URL 校验，这不能证明正式版的微信域名配置已正确。微信后台合法域名、生产 `BASE_URL`、历史数据库中自定义封面与头像需要现场核对。
- 已经保存的临时头像不能通过本次代码恢复，受影响用户需要重新选择并成功上传头像。
